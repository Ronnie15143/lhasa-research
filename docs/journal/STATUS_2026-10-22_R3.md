## 1. ★ l64 的两处结构性 bug（源码级证据）

### 1.1 计时器建错进程 + 删除线程在 victim 内部

`research/l64.c`：

```c
syscall(107 /*timer_create*/, CLK_PROC_CPU, &ev, &id);   /* 在 victim 内部、用自己的 clock */
...
pthread_create(&dth[i], NULL, victim_deleter, &da[i]);   /* 删除线程也在 victim 内部 */
```

- `CLK_PROC_CPU = 2` = `CLOCK_PROCESS_CPUTIME_ID`，指向 **victim 自己的 pid**；
- 删除线程是 victim 的**兄弟线程** ⇒ `de_thread() -> zap_other_threads()` 会先把它们全杀光，
  等到 `release_task(old_leader)` 清 `sighand` 时，victim 内已经没有任何线程在跑
  ⇒ **结构上不可能交错**（HANDOVER_2 §4.2 已推断出这一点，本轮在源码里确认）。
- 正确结构（参考仓库 `docs/139`）：**父进程**用内核内部编码给 victim 建计时器：
  `clockid = ((~(uint32_t)victim_pid) << 3) | CPUCLOCK_SCHED(2)`，
  删除风暴也在**父进程**的线程里（不会被 `de_thread` 干掉）。

### 1.2 父进程“补删”全是 EINVAL，对象从未被释放

`l64.c` 的 phase-1 扫尾：

```c
for (int k = 0; k < n; k++)
    if (syscall(111 /*timer_delete*/, ids[k]) == 0) sw++;
```

`ids[]` 是 **victim 建出来的 timer id**（POSIX timer id 是进程私有的），
父进程拿着它去删必然 `EINVAL`。设备日志实测正是 `del_fail=6144 errno=22 (EINVAL)`，
HANDOVER_2 §4.2 把它解释成“已删完”，实际是 **一次都没删成**。

⇒ 后果链：对象从未释放 → `posix_timers_cache` 的 slab 从未变空 →
**页永远回不到 buddy** → uhid 喷洒再猛也没有可抢的页 → 即使竞态命中也不会 crash。
所以 l62/l63/l64 的 “0 fault” 里至少有一半是假的。

## 3. lhasa 侧重新标定（本轮实测，全部是本机数据，不套用参考机器）

### 3.1 AF_UNIX frag 尺寸：**不是 8192，是 11872**

`unix_stream_sendmsg @ 0xffffffc080214518`：
```
+0xcc  mov w5, #3            ; max_page_order = 3
+0xe8  sub w9, w25, #0xe80   ; data_len = size - 0xe80
```
`alloc_skb_with_frags @ 0xffffffc0801b2084`（+0x264 起）：
```
+0x268 lsl  x8, x27(=0x1000), x22     ; PAGE_SIZE << order
+0x26c cmp  x26(=round_up(data_len)), x8
+0x270 b.lo +0x2a4                    ; 太大 → 降一阶
+0x298 cmp  w22, #1 / b.eq 线性回退 / sub w22,w22,#1
```
- `send(8192)` ⇒ `data_len = 4480` ⇒ 只占 **4480 字节**，页内 4480..8191 不是我们的数据；
- `send(0xe80 + 8192 = 11872)` ⇒ `data_len = 8192` ⇒ **order-1 页、8192 字节全控**。
  （参考机器的 8192 常量在这里会丢一半槽位）

### 3.2 `posix_timers_cache` 几何（与参考机器一致）

```
posix_timers_cache  678  882  384  21  2     ← 384B × 21 对象 / order-1
```
`k_itimer` 384B：`it.cpu.node @ +0xe0`（`posix_cpu_timer_del+0xcc add x8,x19,#0xe0` 侧证），
stride `0x180`，整页 21 个槽位 × `0x180` 恰好铺满 8192。

### 3.3 漏洞仍在（静态判定，见 `research/STATIC_64560_LHASA.md`）

- `posix_cpu_timer_del+0x54 cbz x0,+0xb8` → `+0xc0 brk`（`posix-cpu-timers.c:494`，`__bug_table` flags=0x0903=WARN）
  → `__rcu_read_unlock` → `put_pid` → `mov w0,wzr` 返回 0，**绕开唯一的摘队列点 `+0xec bl disarm_timer`**；
- `__lock_task_sighand` 全函数 0x6c 字节**无 `dmb`/`ldar`**；`release_task+0x2a8 str xzr,[x21,#0x968]` 是**普通 store**；
- `collect_timerqueue` 的 `list_add` 加固是 **`BUG()`**（`CONFIG_BUG_ON_DATA_CORRUPTION=y`）
  ⇒ 悬空节点被复用后是**硬 panic**，不是可恢复的 WARN。

### 3.4 观测通道：dmesg/perf 全封，kprobe 半封

| 通道 | 状态 |
|---|---|
| `dmesg` / `klogctl` | `Permission denied`（shell） |
| `/proc/sys/kernel/tainted` / `panic_on_warn` | `Permission denied` |
| `/sys/fs/pstore` | `Permission denied` |
| `perf_event_open` on tracepoint | **`avc: denied { kernel } tclass=perf_event`**（paranoid=-1 也没用） |
| `/sys/kernel/tracing/kprobe_events` | **0777，shell 可写、可注册探针** ✅ |
| `.../events/kprobes/<ev>/enable` | `-rw-r----- root readtracefs` ⇒ shell 写不进（要 root 写或 permissive） |
| `CONFIG_STATIC_USERMODEHELPER_PATH=""` | ⇒ core_pattern / modprobe 这条 root 通道**确定是死的** |

⇒ **permissive 之前只有 panic 一种信号**；反过来，一旦拿到 permissive，
kprobe(`@ADDR` 任意读)+code 7(root 写 enable) 就能立刻把整条 cred 链接上（docs/158）。

## 5. 战役结果：64560 在本机**机制级不可达**

`l68 panic 800 16 512 150 2 2 15`（风暴拉长到 ~4ms，exec 必落在风暴内）跑到 6,192 exec，
连同 `l65`（8,008）与 `l67`（3,448）共 **17,600 exec、删除 100% 成功、零命中**。
静态复核给了机制解释：

```
begin_new_exec+0x698  bl exchange_tids            ; pid 先换给新 leader
begin_new_exec+0x6a8  bl transfer_pid  (TGID)
begin_new_exec+0x75c  bl _raw_write_unlock_irq    ; tasklist_lock 已放
begin_new_exec+0x76c  bl release_task(leader)     ; 才清 leader->sighand
```

而 `posix_cpu_timer_del` 查 pid 用的是 `PIDTYPE_TGID`（`bic w1,w9,w8,lsr #2`）
⇒ 等 `sighand` 被清零时，tgid 早就指向 exec 线程，**`!sh` 分支没有任何可达时刻**。
详见 `research/64560_DEAD_ON_LHASA.md`。

⚠️ **HANDOVER_2「只剩竞态命中率」的判断作废**：不是命中率低，是窗口不存在。

## 6. 下一步（换路线）

1. 停掉 64560 的所有堆量试验（已停）。
2. 三条候选路线：
   - (a) 换内核 bug：`uhid`（order-1、全内容可控、非特权）依然是现成的回收原语，
     目标改成"任何可达的 UAF/OOB"，不再依赖 posix-cpu-timers；

     的写规则只有 `update_engine_common`（`UNLOCK_PATHS.md`），需要该域的代码执行 +
     不用签名的载荷路径；`IMQSNative code 7` 只能写字符串（8 MB ESP 写不动），
     `CONFIG_STATIC_USERMODEHELPER_PATH=""` 封死 core_pattern/modprobe；
   - (c) 复核 `de_thread` 在**别的**内核路径上是否还有可用的 `sighand == NULL` 暴露面
     （本轮已排除非 leader exec 这一条）。
3. 已有可复用资产：`l65/l67/l68`（触发/回收/夺页 + `MSG_PEEK` 判据）、`l66_oracle`、
